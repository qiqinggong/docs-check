# 迁移与发行准备

目标是建立独立源码仓库和携带依赖的 npm 发行包，保持开发目录与已安装版本隔离。

## 确定的交付方式

- 仓库与包名为 `docs-check`，候选版本为 `0.2.0`。
- 同仓库 GitHub Releases 分发 `.tgz` 与校验文件，当前不发布 npm registry。
- 源码锁文件维护依赖组合，打包阶段生成 shrinkwrap；当前迁移不升级检查引擎。
- 命令、项目配置子集、只读检查与退出码契约保持。
- 自有代码采用 MIT，依赖保留原有许可。

## 当前实施边界

已授权工作包括归档原始材料、复制并独立维护源码、实现安装与发行流程、构建本地候选包并在临时 prefix 预检。内部原始计划及审查历史保存在本机独立归档和仅本机分支，不进入公开历史。

本地预检完成后暂停并交人工验收，未获验收及后续授权时不推送、不发行、不切换正式命令。消费项目保持只读，项目推荐基线、验收记录及环境记录更新留到最后单独授权。

## 验收与后续

本地验收核对包内容、锁文件、源码提交、SHA-256、离线安装、实际安装入口回归、未知入口保护及失败恢复，记录真实环境和未覆盖范围。

后续远端验证覆盖 macOS/Linux、Node 22/24。最终包由单一构建作业产生，矩阵、草稿附件和消费验收使用摘要一致的产物。不同摘要须重新验收，不能用相同版本号替代。

具体操作见 [开发与发行](../../releasing.md)，执行结果以实际生成的本机报告及后续 CI 记录为准。
