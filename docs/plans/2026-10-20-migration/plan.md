# 迁移与发行

目标是建立独立源码仓库和携带依赖的 npm 发行包，保持开发目录与已安装版本隔离。

## 确定的交付方式

- 仓库与包名为 `docs-check`，首个公开版本为 `0.2.0`。
- 同仓库 GitHub Releases 分发 `.tgz` 与校验文件，当前不发布 npm registry。
- 源码锁文件维护依赖组合，打包阶段生成 shrinkwrap；本次迁移未升级检查引擎。
- 命令、项目配置子集、只读检查与退出码契约保持。
- 自有代码采用 MIT，依赖保留原有许可。

## 实施结果

原始材料归档、独立源码仓库、安装与发行流程、本地候选包及临时 prefix 预检已完成。内部原始计划及审查历史保存在本机独立归档和仅本机分支，不进入公开历史。

远端 CI、最终包验收及正式命令切换已完成。经分阶段人工验收与授权，现已公开 [0.2.0 Release](https://github.com/qiqinggong/docs-check/releases/tag/v0.2.0)，匿名下载附件与验收包逐字节一致；旧运行位置仅保留迁移说明，完整恢复归档保留在本机。

项目推荐基线、消费验收记录及环境记录已按最后授权更新。迁移实施完成，最终人工验收状态保留在本机收尾记录中。

## 验收与后续

本地验收核对包内容、锁文件、源码提交、SHA-256、离线安装、实际安装入口回归、未知入口保护及失败恢复，记录真实环境和未覆盖范围。

远端验证已覆盖 macOS/Linux、Node 22/24。最终包由单一构建作业产生，矩阵、正式附件和消费验收使用摘要一致的产物。不同摘要须重新验收，不能用相同版本号替代。

具体操作见 [开发与发行](../../releasing.md)，执行结果以实际生成的本机报告及 CI、Release 记录为准。
